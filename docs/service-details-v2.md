# 服务详情首版 V2

本版为用户授权先上站、再逐项调整的服务草稿。覆盖所有内部详情入口，不填写价格、案例、成绩、保证录用或未确认的团队成员。三张外链介绍卡保留原跳转。

纸片与外部背景保持原样。电脑左右两栏，手机上下排；手机内容较多时在同一张纸片内部滚动，保持可读字号，不缩字硬塞一屏。

## 求职规划

先选准方向，再决定怎么准备。

想转向 LLM 相关岗位，却不知道已有经历能用上多少？先把目标、差距和准备顺序理清。

准备材料：一份现有简历、想投的岗位，以及你能投入的时间。

实际过程：
- 拆岗位：一起看具体招聘要求，分清必备能力和加分项。
- 盘经历：看简历、项目与作品，找能证明能力的内容。
- 排顺序：结合求职时间，把要补的内容排出轻重缓急。

交付内容：
- 岗位方向：主攻什么、备选什么，以及选择依据。
- 材料建议：简历哪些要改，哪些项目还缺有说服力的证据。
- 准备路线：优先补什么，每一步做出什么成果再往下走。

先解决「往哪走、先做什么」。

联系引导：发来简历、目标岗位和预计求职时间，我们先看从哪里开始。

## 定制成长

围绕你要做的工作，学会，也做出来。

从岗位需要的能力倒推学习与实践。已有基础继续用，缺的部分通过讲解、任务和反馈补上。

准备材料：你的目标方向、现有基础；已有规划也可以直接带来。

实际过程：
- 定内容：按目标选择产品、工程、算法或具体业务领域的学习重点。
- 做实践：围绕真实问题设计任务，例如 RAG、Agent、AI Coding 与系统接入。
- 逐步打磨：一起看实现、结果与问题，补原理、改方案，练清楚为什么这样做。

交付内容：
- 个人学习安排：明确学什么、练什么，用什么成果检查进展。
- 项目与作品：按约定方向完成实践，留下代码、方案或产品原型。
- 能力反馈：记录已掌握什么、还卡在哪里，继续调整学习任务。

具体方向与项目，先看需求和基础再定。

联系引导：说说你的目标岗位、当前基础，以及最想补上的能力。

## 全程陪跑

有问题时有人一起拆，有进展时一起复盘。

学到一半卡住、项目讲不清、面试后不知道改哪里。把这些具体问题，放进持续跟进的过程里。

准备材料：你的阶段计划、当前成果和最近遇到的问题。

实际过程：
- 跟进任务：对照计划看完成情况，拆开卡点，调整下一步。
- 打磨表达：围绕简历与实际项目追问，练业务价值、技术选择和个人贡献。
- 复盘面试：结合真实反馈分析问题，调整准备重点与投递方向。

交付内容：
- 阶段问题清单：这一轮完成了什么，哪里需要返工或补强。
- 面试复盘记录：哪些回答缺证据，哪些知识和表达需要再练。
- 下一轮行动：把反馈变成具体任务，继续跟进执行结果。

沟通节奏、周期与支持范围，开始前一起约定。

联系引导：告诉我们你在准备的阶段，以及目前最卡的一件事。

## 项目咨询

这件事值得做吗？该从哪里做起？

有业务想法，也看到 AI 的可能，但需求、技术和投入还没想清楚。我们一起把判断依据摆出来。

准备材料：业务场景、现有流程，以及你最想改善的一个问题。

实际过程：
- 看现场：梳理谁在什么场景下遇到问题，现有系统和数据能用上什么。
- 拆方案：讨论 AI 是否适用，对比实现路径、技术选型与系统边界。
- 定起步：明确先验证什么、需要哪些资源，以及如何判断值得继续。

交付内容：
- 问题与范围：目标、优先级、输入条件，以及这次先做到哪里。
- 方案与取舍：流程、架构或原型建议，关键选择与依赖条件。
- 试点计划：验证步骤、验收依据，以及人力、时间和成本估算。

可以先从一个流程、一个功能开始。

联系引导：发来场景、现有做法和预期变化，有资料或草图也可以一起发。

## 方案交付

把想法做成能用、能验收的东西。

从原型验证到开发落地，围绕约定范围推进。让需求、实现和验收对上，而不只停在演示里。

准备材料：需求或已有方案、运行环境，以及期望完成的时间。

实际过程：
- 定验收：把功能、使用流程和验收方式写清楚，再确定交付边界。
- 做实现：按项目需要推进产品原型、Agent / RAG、工具与系统集成。
- 验结果：走实际使用流程，处理问题，整理运行与交接资料。

交付内容：
- 约定成果：原型、应用或系统功能，按确认的范围交付。
- 验证记录：记录测试场景、结果和已知问题，对照标准验收。
- 交接资料：按范围提供源码、部署说明和必要的使用文档。

开发范围、里程碑与交接内容，先确认再执行。

联系引导：说说要做什么、已有些什么，以及期望的时间和预算范围。

## 定制化 WeChat Bot

让 AI 群友，按你的群聊方式参与。

接话、记住上下文、整理群报。结合你的群聊场景，配置它说什么、什么时候说、什么时候安静。

准备材料：群的用途、想要的角色，以及几个典型对话场景。

实际过程：
- 定角色：确定人设、语气和回复场景，选择需要的记忆与群报功能。
- 定规则：设置触发方式、参与频率和静默时段，减少不合时宜的打扰。
- 试运行：基于桌面自动化方案联调，用约定场景检查回复与运行表现。

交付内容：
- 角色与参与规则：可调整的人设、回复方式和群聊参与配置。
- 所选能力：按约定组合上下文记忆、群报与互动功能。
- 运行与调整说明：交代运行条件、配置方法，以及如何暂停和调整。

先确认桌面环境与功能适配，再确定实施范围。

联系引导：说说群用来做什么、希望 Bot 做什么，以及准备使用的桌面环境。

## 团队介绍

一个需求，往往需要不止一种视角。

工程、算法、HR 与业务专家一起参与。围绕具体问题协作，把技术实现、岗位理解与业务使用连起来。

准备材料：你的目标、当前问题和已有材料。

实际过程：
- 工程视角：关注实现、集成、运行与交接，让方案能够落地。
- 算法视角：关注模型选择、数据与评测，让效果有依据。
- 业务与招聘视角：关注使用场景、岗位要求与表达，让成果对得上实际需求。

交付内容：
- 明确目标：先判断要解决什么，以及需要哪些专业视角。
- 明确分工：根据需求确认参与角色、职责和沟通方式。
- 明确交付：把范围、过程和验收说清楚，再开始协作。

具体成员与参与方式，在沟通需求后确认。

联系引导：发来你希望解决的问题、已有条件和预期目标。
